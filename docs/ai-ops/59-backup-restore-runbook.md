# 備份與還原操作手冊

本頁是事故時的「先確認、再動手」清單。它只描述流程，不會自動連線、備份或還原任何資料庫。

## 先看這裡（給老闆）

1. 先停止會寫入資料庫的工作，記下目前時間、部署版本與事故原因。
2. 確認要操作的是哪一個資料庫。**不要把正式站的連線字串貼到聊天、終端輸出或報告。**
3. 先做一份新的備份，再做還原。還原前要得到老闆明確確認，並記下確認人與時間。
4. 還原完成後，在拋棄式環境先跑完整性檢查與唯讀頁面驗收；確認無誤才恢復寫入工作。
5. 留存備份檔雜湊、資料庫識別（不可含密碼）、操作者、開始/結束時間與驗收結果。

## 備份流程

### PostgreSQL

使用可信任環境產生 custom-format dump（範例中的路徑是本機暫存路徑，不是正式資料庫名稱）：

```text
pg_dump --format=custom --file=backup-YYYYMMDD-HHmm.dump "$DATABASE_URL"
sha256sum backup-YYYYMMDD-HHmm.dump
```

實際執行前必須確認：

- `DATABASE_URL` 是預期的資料庫，且不是測試庫、陌生庫或別人的店鋪。
- 備份檔放在受限的加密儲存，不進 Git、不放公開物件儲存、不貼入 issue。
- 指令輸出不含連線字串；報告只記檔名、SHA-256、大小與時間。
- 使用 `scripts/verify-backup.mjs` 做唯讀檢查時，仍要提供明確的 dump/暫存庫參數。

## 還原流程

### 先在拋棄式資料庫演練

1. 建立全新的 PostgreSQL 資料庫或一次性容器，使用假資料與隔離網路。
2. 將 dump 還原到該環境，不要在正式資料庫上試跑。
3. 執行 `scripts/audit-data-integrity.mjs`，確認沒有孤兒訂單、非法狀態、負金額或重複代號等異常。
4. 重新跑唯讀頁面、API 健康檢查與必要測試；所有結果留存原文。
5. 演練通過後才可排正式還原時段。

### 正式還原（需要老闆確認）

1. 設定維護公告並暫停寫入；先確認沒有進行中的 migration、匯出或批次工作。
2. 再核對一次目標資料庫與備份 SHA-256。**不確定就停。**
3. 由具備資料庫權限的人執行還原，另一人旁觀記錄；不得用聊天機器人或自動代理直接代按確認。
4. 還原後先只讀驗收：`/api/healthz`、後台登入牆、公開連結不洩漏成本/個資、訂單與店鋪筆數。
5. 老闆確認驗收通過後才解除維護；保留還原前後的稽核紀錄。

## Replit 部署資料庫政策（待確認）

本 repo 尚未把 Replit Production Database 的備份、還原權限、保留期限、時間點還原與「Approve and publish」的資料庫行為定義成正式規格。**在 Replit 介面確認前，不假設 Preview 與 Production 共用資料庫，也不勾選會覆寫既有資料的選項。**

老闆需向 Replit 專案確認並回填：

- Production database 的實際備份入口、保留天數與下載/刪除權限。
- Publish/Republish 時是否只套用 additive migration，是否可能複製或覆寫資料。
- 是否能建立 deployment preview database，以及 preview→production 的還原與回復步驟。
- 發生誤套 migration 時的回復窗口、支援窗口與責任人。

在上述答案取得前，本專案只允許拋棄式資料庫演練；任何正式庫還原都是停止點。

## 事故記錄欄位

每次備份/還原至少記錄：

| 欄位             | 內容                                            |
| ---------------- | ----------------------------------------------- |
| 事件編號         | 不含個資的內部編號                              |
| 操作者／確認人   | 帳號或代號，不放 token                          |
| 目標環境         | preview / production（不得寫連線字串）          |
| 備份檔與 SHA-256 | 檔名、大小、雜湊、產生時間                      |
| 動作             | backup / rehearsal restore / production restore |
| 完成時間         | 開始、結束、是否成功                            |
| 驗收             | healthz、完整性、關鍵頁面與測試結果             |
| 後續             | 是否解除維護、待辦與負責人                      |
