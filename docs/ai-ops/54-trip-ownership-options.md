# Trips / trip_routes 歸屬方案（BATCH-20 包 7）

日期：2026-08-01  
性質：唯讀設計報告；本文件不改 schema、migration 或 trips 路由。  
現況基準：`lib/db/src/schema/trips.ts` 的 `trips` 沒有 `store_id`；`trip_routes` 以 `trip_id` 隸屬行程。`artifacts/api-server/src/routes/trips.ts` 的 GET/POST/PATCH 行程與路線端點目前只使用 `requireAuth`，沒有店主或店鋪範圍條件。

## 1. 先講結論

目前系統實際上採用「所有已登入商家共用行程資料」的單租戶假設。這在只有一個老闆、只有一個店鋪時可運作，但一旦增加第二家店，任何登入商家都可能讀取、修改其他店的行程、匯率與交通成本；這些欄位又是商品交通成本與毛利的輸入，因此不能用補測試或路由小修假裝解決。

保守建議：若產品目標是多店／多商家，選 **方案 A：每店獨立**；先由老闆確認既有行程要歸到哪一家店，再另開 schema＋migration＋路由授權包。若產品明確維持單一店鋪，才可選 B，但必須把「單租戶」寫成正式邊界與部署前提。方案 C 只有在確定需要跨店共用且能接受較高授權複雜度時才值得做。

## 2. 不變的成本快照原則

訂單建立時由既有 `createInitialOrderProfitSnapshot`／`calculateProductUnitProfit` 產生快照；Q63 規定快照寫入後永久定格。無論最後選 A、B 或 C，既有訂單的九個單品快照欄、cart 品項快照與整單合計都不可因行程重新歸屬或匯率修改而重算。遷移只能補上資料歸屬與授權，不得回填或改寫既有訂單快照；新單才使用當下可用的行程資料。

## 4. 方案 A 的建議施工順序（不代表已授權施工）

1. 老闆先提供既有行程的店鋪歸屬表；不能以猜測或目前唯一店鋪直接回填。
2. 新增 nullable `trips.store_id`、FK、索引；先做資料盤點與回填 dry-run，確認每筆行程恰有一個店鋪。
3. 完成回填後再加 NOT NULL／必要 check，並讓 `trip_routes` 的查詢一律透過所屬 trip 範圍。
4. 所有 trips/trip_routes 路由套用 `requireAuth` → `verifyStoreOwner`（或等價的 store scope）→ 資料查詢／寫入；跨店錯誤不洩漏資料存在與否。
5. 檢查商品的 `trip_route_id` 掛載流程：商品店鋪與 route 所屬店鋪不一致時拒絕；既有商品掛載先盤點再決定處置，不能默默換 route。
6. 用拋棄式資料庫演練 migration、跨店讀寫負向測試、快照凍結測試，再考慮正式庫套用。

## 5. 需要老闆拍板的題卡

### Q-TRIP-OWN-1：行程資料歸屬

- **A（建議）**：每家店只管理自己的 trips／trip_routes；跨店不可見。
- **B**：平台共用；目前維持單租戶假設，未來多店另開專案。
- **C**：一店擁有，其他店以明確分享關聯使用，可設定唯讀或可編輯。

影響：A 需要既有資料回填；B 沒有立即 migration 但保留多租戶風險；C 需要新權限模型與分享 UI。未收到選項前，不實作 schema、migration 或路由。

### Q-TRIP-OWN-2：既有行程回填規則（只有選 A/C 才適用）

1. 老闆提供每筆既有 trip 對應店鋪（最安全）。
2. 若確定目前資料全屬唯一店鋪，可由老闆明確確認「全部回填至該店」。
3. 無法判定的列保留待確認並阻止收緊 NOT NULL；不得自動猜測。

### Q-TRIP-OWN-3：分享後誰能修改（只有選 C 才適用）

- 唯讀分享（建議預設）：可用於新單成本計算，但只有 owner 可改成本。
- 可編輯分享：被分享店主可改路線成本；每次修改需 audit，並明確影響後續新單。

### Q-TRIP-OWN-4：商品掛載與跨店行程

- **嚴格同店（建議）**：商品與 route 必須同店，跨店掛載拒絕。
- **允許已授權分享**：只有方案 C 且具有效分享權限時允許；訂單快照需保存可追溯的來源資訊（另案拍板）。

## 6. 本包界線與未解問題

- 本包只提供選項、影響與題卡；沒有新增或修改任何表、migration、route、UI 或測試。
- 尚未決定行程是每店獨立、平台共用或可分享；因此沒有「已完成的歸屬修正」可宣稱。
- 正式施工前仍需確認既有 trips／商品 route 掛載資料的清單，以及是否要把 route 使用來源加入訂單診斷資訊；後者不能改寫既有成本快照。
